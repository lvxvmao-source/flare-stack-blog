### 关键修复：vite.config.ts paraglide cleanOutdir
- **问题**：`@inlang/paraglide-js` Vite 插件在 `buildStart()` 中首次编译时 `cleanOutdir: true`（删除 src/paraglide 目录后重新生成），与 `@cloudflare/vite-plugin` 的 workerd SSR runner 产生竞态条件——workrunner 尝试加载模块时文件正在被删除/重建，导致 "Failed to load url .../src/paraglide/messages.js" 500 错误。

- **原理**：unplugin.js 中 `...args` 展开在 `cleanOutdir: previousCompilation === undefined` 之后，传入的 `cleanOutdir: false` 覆盖计算值。

1. **头部裁切**：根因是 oml2d 在模型加载后调用 `stage.reloadStyle(this.models.modelSize)`（index.js:28375）覆盖我们设的 stageStyle；且 Miku model3.json 缺 Cubism `Layout` 段，pixi 报告的 bounds 比实际画布矮，头顶超出舞台。方案：去掉无效固定 stageStyle，新增 `fitStageToModel()` 在 `loadOml2d` 后立即运行，测量真实 `models.modelSize`（用 `models.model.once("ready"/"modelLoaded")` 事件等待），放大舞台并下移模型（`STAGE_MARGIN_TOP=0.45`），给头顶留白。
2. **仅前台显示（不含欢迎页、不含后台）**：在 `__root.tsx` 新增 `Live2dVisibilityController`（client 组件，用 `useRouterState` 取 pathname，`useEffect` 调 `setLive2dVisible(!(pathname==="/"||pathname.startsWith("/admin")))`），挂在 `<body>` 内 `<Scripts />` 前；移除 welcome/page.tsx 里重复的 `setLive2dVisible` effect（避免时序冲突）。隐藏实现：`setLive2dVisible` 切 `oml2d-hidden-welcome` body class + 注入 CSS `display:none!important` 命中 `.oml2d-stage/.oml2d-menus/.oml2d-tips/.oml2d-statusBar`。
3. **后台"返回前台" → /home**：`src/routes/admin/route.tsx` 第 88 行 `<Link to="/">` 改为 `to="/home"`（仅此 1 行实质改动）。

### 关键环境发现：vite dev SSR 500（fetch failed）
- 现象：本沙箱 `vite dev` 下 `/`、`/home`、`/admin` 全部 500，错误 `miniflare ... fetch failed`，无更具体信息。
- 根因：顶层 `wrangler.jsonc` 的 bindings 全是 remote（D1 带 `database_id`、`r2/kv/ai remote:true`），miniflare 把远程 binding 操作通过 `fetch` 代理到 Cloudflare API，沙箱无凭证（CLOUDFLARE_API_TOKEN）+ 无网络 → 必然 500。与本次 client-side useEffect/router 改动无关（改动均在 useEffect 内，SSR 不会执行；`setLive2dVisible` 在 `document===undefined` 时 early return）。
- 用户自己的环境有这些 binding（所以能看到站娘），因此改动在其环境可直接生效。
- **沙箱本地渲染办法**：用 `env.test`（wrangler.jsonc 的 test 环境是本地 binding，无需凭证/网络）或在 `.dev.vars` 配 `CLOUDFLARE_API_TOKEN` + account id；但即便 SSR 200，curl 仍看不到 canvas 站娘（client 渲染需真实浏览器），故 head 裁切/显隐仍须用户浏览器确认。
