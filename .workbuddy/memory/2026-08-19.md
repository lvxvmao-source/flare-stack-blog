# 2026-08-19 Live2D 站娘"改完不加载"排查

## 现象
用户反馈：上一轮四项修改后，站娘"连加载都加载不出来了"（此前能看到、只是头部裁切）。

## 排查结论
- 核对 oml2d 0.19.3 真实 API：`setModelPosition` 是顶层实例方法（dist/index.js:28339，内部 `this.models.setPosition`）；`models.modelSize` getter（21144）；`stage.reloadStyle`（6482）；`model.once("ready"/"modelLoaded")`（16068）均存在 → 我的改动 API 名称正确，不会阻断加载。
- `PublicLayout`（public-layout.tsx:153）仍正常挂载 `Live2dWidget`；`Live2dVisibilityController`（`__root.tsx:141`）在 `/home` 显示、仅在 `/` 与 `/admin*` 隐藏，逻辑正确。

## 发现的真实 bug（已修）
- `fitStageToModel()` 在 `loadOml2d` 返回后同步调用，此时 `internal.models.model`（pixi 模型）尚未创建，`internal.models?.model?.once("ready"/"modelLoaded", apply)` 被 `?.` 短路成 no-op → 两个监听根本没注册上。头部修正只靠 60 帧(~1s) rAF 轮询，对 32MB Miku 多半来不及 → 头部修正失效（但不会导致"完全不加载"）。
- 修复：改为稳健 rAF 轮询（上限 600 帧≈10s）+ `applied` 守卫 + try/catch，绝不在尺寸计算抛错阻断加载；模型就绪后头部修正必定生效。`tsc --noEmit` + `biome check` 均 0。

## 沙箱 SSR 限制（关键，影响能否本地复现）
- 即使用本地 `env.test`（`wrangler.jsonc` 的 test 环境=本地绑定，非 remote），`CLOUDFLARE_ENV=test vite dev` 下 `/`、`/home`、`/admin` 仍全部 500 `fetch failed`（miniflare 在本沙箱网络下 `fetch` 必败），与代码无关。
- 故无法在沙箱渲染页面 / 看 canvas 站娘；client 端问题只能靠用户浏览器控制台报错定位。

## 给用户的最可能原因 + 下一步
- 最可能：按用户上轮要求"不包括欢迎页面"，站娘现在在欢迎页 `/` 隐藏（正确行为）；用户开站根落在 `/` 看不到 → 点"进入"到 `/home` 才显示。
- 若 `/home` 也无站娘：是 client 端错误，需用户 F12→Console 粘贴红色报错（尤其含 live2d/oml2d 或 "is not a function"）才能精确定位。
- 另需确认站点配置 `live2dEnabled:true` 且 `live2dModel:"miku"`（admin / blog.config）。
